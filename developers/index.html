Build with UNTERGRUND.

Find public releases, creator profiles, and live Club Rooms. The API is read-only and needs no API key.

OpenAPI 3.1 specification

Get your first release

curl -fsS https://www.untergrund.sh/api/v1/tracks

Pick an id from data.tracks, then look up that release:

curl -fsS "https://www.untergrund.sh/api/v1/tracks/$TRACK_ID"
GET /api/v1/tracks
Up to 60 recent public releases, newest first.
GET /api/v1/tracks/{id}
Track metadata, a public link, an embed URL, and creator credit when available.
GET /api/v1/artists/{handle}
A public creator profile and its releases.
GET /api/v1/rooms
Public Club Rooms that are currently on air. An empty list means none are live.

Embed a track

Replace TRACK_ID with a release ID, or set the iframe’s src to data.track.embedUrl. Playback starts when a visitor presses play.

<iframe src="https://www.untergrund.sh/embed.html?t=TRACK_ID"
  title="Play this track on UNTERGRUND" width="100%" height="152"
  style="border:0;max-width:560px" loading="lazy"></iframe>

Responses and limits

Successful data requests return {"data":{…}}. Errors return {"error":{"code":"…","message":"…"}}. The OpenAPI URL returns the specification directly.

Cross-origin reads are allowed. Releases and profiles may be cached for 30 seconds; live rooms for 5 seconds. When Redis is configured, origin requests share a limit of 120 per IP per minute across data endpoints. On 429, wait for the number of seconds in Retry-After before retrying.
